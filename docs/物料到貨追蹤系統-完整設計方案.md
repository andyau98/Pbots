## 第一部分：現有系統架構（PBots 簡介）

PBots 係一個基於 `whatsapp-web.js` + `LocalAuth` 嘅 WhatsApp 機器人，用於**幕牆工地管理**。現有功能包括：管理員認證、考勤管理（判頭登記+每日申報人數→寫入Excel）、物料圖紙搜尋（POR目錄索引+SQLite+DWG位置圖比對）、照片收集→PDF生成、香港天氣/地盤新聞。

### 現有技術棧

| 技術 | 用途 | 位置 |
|------|------|------|
| `whatsapp-web.js` | WhatsApp 連接 | `src/index.js` |
| `better-sqlite3` | SQLite 資料庫（WAL模式） | `src/core/database.js` |
| `exceljs` | Excel 讀寫（保留格式） | `skills/workerAttendance.js` 使用中 |
| `tesseract.js` ^7.0.0 | OCR 文字辨識 | 已安裝 |
| `sharp` ^0.34.5 | 圖像預處理 | 已安裝 |
| `pdf-parse` ^2.4.5 | PDF 文字提取 | 已安裝 |
| `pdfjs-dist` | PDF 備用提取 | `skills/tgParser.js` 已有 |
| `node-cron` | 排程任務 | `src/core/scheduler.js` |

### 核心架構（新功能必須遵循）

| 組件 | 檔案 | 用途 |
|------|------|------|
| **SessionManager** | `src/core/sessionManager.js` | 互動式問答流程。群組觸發→私訊問答→結果發回群組。支援超時、取消、群組鎖定 |
| **CommandRouter** | `src/core/commandRouter.js` | 命令登記+權限檢查+路由分發。`#` hash命令、`!` prefix命令 |
| **DataStore** | `src/core/dataStore.js` | JSON 資料層（管理員/封鎖/群組/設定），不可直接讀寫檔案 |
| **Database** | `src/core/database.js` | SQLite singleton（`pbots.db`），用於圖紙索引同大量結構化數據 |
| **MonitorServer** | `src/core/monitorServer.js` | HTTP 儀表板 :3456，純 `http.createServer` 無框架，`switch(url.pathname)` 路由 |
| **Scheduler** | `src/core/scheduler.js` | node-cron 排程，現有 9:00AM 考勤 + 12:00PM 圖紙索引重建 |

### POR 圖紙目錄結構

```
Z:\POR\01 POR ISAAC\
  POR1469 HGRH-BTB0102-FST4152B 铁件加工图 (For BTB_3F~11F)\
    ├── 數量表.xlsx              ← 原始數量表（格式不一，不修改）
    ├── _到貨記錄.xlsx            ← 🆕 系統生成嘅到貨記錄
    ├── ACD0060.dwg              ← 加工圖
    ├── ACD0061.pdf
    ├── WCA-TG-FAC-0013.dwg     ← TG 位置圖
    └── ...
  POR1470 WCA-FAC1023A 铝板加工图 (For 5F~10F)\
    └── ...
```

**關鍵事實**：
- POR folder 名含唯一編碼（如 `FST4152B`），絕對唔會重複
- 每個 folder 內有數量表 Excel（格式各異）、加工圖檔案、TG 位置圖
- `files` 表已有 49,518 筆圖紙索引（por、materials、folder、ext、has_tag）
- `tg_mapping` 表有加工圖號 ↔ 位置圖雙向索引（drawing_number + file_path）
- `folder_cache` 表有每個 folder 嘅 drawing_numbers 列表

## 第二部分：物料到貨追蹤系統設計

### 用戶完整需求流程

```
到貨 → WhatsApp bot 影相 or PDF 貨單
→ 機械人自動對加工圖上的物料
→ 在 POR 的數量表中 highlight 已到貨的物料
→ 日期及落貨擺放位置同時存儲在加工圖的 folder 上
→ 在 UI 上顯示已到的貨同時顯示未到的貨
→ 將未到的貨分析列表
→ 按單上的供應商追貨
→ 將已上所有動作記錄所有貨品狀態，點擊每個連結清楚所有加工圖同位置
→ 再將位置圖上的 mark highlight 清楚用位置圖顯示來貨
```

### 關鍵用戶確認

| 事實 | 影響 |
|------|------|
| 貨單上**一定有** `FST4152B` 唯一編碼 | 步驟2 = SQL精確匹配，100%準確 |
| 數量表係 Excel .xlsx，**每個 folder 格式不一** | 需自適應讀取，不能靠固定 cell |
| Folder 名 = 單號，數量表一定喺 folder 內 | 鎖定 folder 就等於鎖定全部資料 |
| 加工圖號可能跨項目重複 | 但 folder 內唯一，folder 先鎖定就零衝突 |
| **唔修改原數量表 Excel** | 另建獨立 `_到貨記錄.xlsx` |
| WhatsApp 只做即時回饋，唔做分析工具 | 詳細分析在 Excel 總表 + Web UI |

### 步驟 1：WhatsApp 收貨 + 貨單資料提取

#### 命令設計

| 命令 | 模式 | 功能 |
|------|------|------|
| `#到貨` | 引導模式 | 逐步問：單號 → 數量 → 位置 → 影相 |
| `#到貨快 <單號> <數量> <位置>` | 快指令 | 一行輸入 + 附相 |

#### 貨單格式分類

| 格式 | 提取方式 | 難度 |
|------|----------|------|
| A. 供應商印刷送貨單 | OCR → 正則匹配 | 🟢 易 |
| B. 供應商 PDF 送貨單 | pdf-parse 直接提文字 | 🟢 易 |
| C. 手寫送貨單 | 幾乎無法自動 → 人手輸入 | 🔴 難 |
| D. WhatsApp 文字訊息 | 直接正則解析 | 🟢 易 |

#### 豆包 AI 視覺核心（2025-06-16 更新，取代傳統 OCR）

用戶與 Gemini 商議後，以**豆包 AI（Doubao）視覺辨識**取代傳統 OCR。

**新核心流程**：

```
[管工 WhatsApp 上傳相片]
         │
         ▼
[Node.js 下載相片至本地暫存]              ← mediaDownloader（現有）
         │
         ▼
[OpenCLI 呼叫豆包網頁版]                  ← 🆕 AI 視覺核心
  相片 → 豆包讀圖 → 精確轉為乾淨 JSON
         │
         ▼
[本地 SQLite / 資料夾檢索]                ← 根據唯一編碼定位 POR folder
         │
         ▼
[exceljs 精確更新 Excel]                  ← 掃描圖號、累加數量、highlight
         │
         ▼
[WhatsApp 機器人自動回覆確認]             ← SessionManager
```

**豆包輸出 JSON 格式**：

```json
{
  "orderNumber": "FST4152B",
  "projectCode": "HGRH",
  "materialCode": "FST",
  "deliveryDate": "2026-06-13",
  "supplier": "XX鋼材供應有限公司",
  "items": [
    { "seq": 1, "drawing": "ACD0060", "description": "鋁板 2mm", "quantity": 50, "unit": "件" }
  ]
}
```

**雙軌架構**：豆包優先 → tesseract + Plan C 做 fallback

**OpenCLI 可行性驗證**（2025-06-16）：

| 項目 | 狀態 |
|------|------|
| OpenCLI | ✅ [jackwener/OpenCLI](https://github.com/jackwener/opencli)，npm `@jackwener/opencli` v1.8.4，~22k stars |
| 持久登入 | ✅ OpenCLI 複用現有 Chrome login session |
| 輸出格式 | ✅ 機械人 prompt 指定固定格式 → Node.js 正則解析，唔依賴 JSON 穩定性 |

**整合方式**：Node.js `child_process.exec()` 調用 `opencli browser` 命令。需安裝 Chrome Browser Bridge Extension。

### 步驟 2：落單號 → POR Folder 精確匹配

#### 最終方案（已解決 ✅）

```
貨單上一定有 FST4152B 唯一編碼
  → OCR 提取: [A-Z]{2,4}\d{3,6}[A-Z]?
  → SQL: SELECT DISTINCT por FROM files WHERE por LIKE '%FST4152B%'
  → 必定唯一（4152B 絕對唯一）
  → 鎖定 folder ✅
```

項目碼+物料碼組合唯一，加工圖號 folder 內唯一。**100% 準確，零人手介入。**

### 步驟 6：到貨狀態即時回饋 + 後台分析

#### 設計原則

> **WhatsApp 只做即時回饋。** 處理完貨單即刻話俾管工知狀態。詳細分析喺 Excel 同 Web UI。

#### WhatsApp 即時回饋三種情況

**全部到齊 ✅**
```
📋 *到貨確認 — POR1469 HGRH-FST 铁件加工图*
✅ 此單已全部到齊 (24/24項)
📅 到貨日期: 2026-06-13
📍 存放位置: 5樓B區
```

**部分到齊 ⚠️（含到貨歷史）**
```
📋 *到貨確認 — POR1469 HGRH-FST 铁件加工图*
⚠️ 此單部分到齊 (21/24項)

📦 到貨歷史:
  • 2026-06-10: 18項 (50件) — 5樓A區
  • 2026-06-13: 3項 (25件) — 5樓B區 ← 今次

尚欠以下物料未到：
  • ACD0062 鋁板3mm — 欠15件
    上次到貨: 2026-06-10 | 位置: 5樓A區
  • ACD0063 鋁角 — 欠20件
    ❌ 從未到貨 — 需要新貨單
  • ACD0065 鐵碼 — 欠5件
    上次到貨: 2026-06-13 | 位置: 5樓B區
```

#### 欠貨自動分類

| 標記 | 條件 | 含義 |
|------|------|------|
| ❌ 需新貨單 | total_received = 0 | 從未到過，等供應商送 |
| 📍 需更新位置 | total_received > 0 但位置為空 | 已到過，補記錄位置 |
| ⚠️ 尚欠 N 件 | 0 < received < required | 部分到貨 |

#### `#到貨查詢 <單號>` 命令

管工可隨時查任何單嘅狀態。同現有 `#Drawing` / `#dwgfind` 查詢機制連動。

#### 🔴 改善：長期未到齊排程提醒

每星期一早上檢查 → 超過 30 日未到齊 → WhatsApp 通知管理員。

## 第三部分：資料庫設計

### 新 Table（在 `pbots.db` 新增）

```sql
-- deliveries: 每次到貨記錄
CREATE TABLE deliveries (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    delivery_date DATE NOT NULL,
    order_number TEXT NOT NULL,          -- 唯一編碼，如 FST4152B
    por_folder TEXT,                    -- 匹配到嘅 POR folder
    drawing_numbers TEXT DEFAULT '[]',  -- JSON: 加工圖號陣列
    quantity REAL NOT NULL,
    unit TEXT DEFAULT '件',
    supplier TEXT,
    storage_location TEXT,
    photo_paths TEXT DEFAULT '[]',      -- JSON: 貨單相片路徑
    recorded_by TEXT NOT NULL,
    recorded_name TEXT,
    status TEXT DEFAULT 'received',
    notes TEXT
);

-- material_inventory: 物料庫存狀態
CREATE TABLE material_inventory (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    drawing_number TEXT NOT NULL UNIQUE,
    por_folder TEXT NOT NULL,
    material_code TEXT NOT NULL,
    description TEXT,
    total_required REAL DEFAULT 0,
    total_received REAL DEFAULT 0,
    last_delivery_date DATE,
    last_storage_location TEXT,
    status TEXT DEFAULT 'pending',      -- pending/partial/complete
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- delivery_actions: 審計日誌
CREATE TABLE delivery_actions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    delivery_id INTEGER REFERENCES deliveries(id),
    drawing_number TEXT,
    action TEXT NOT NULL,               -- received/edited/queried/exported/reminded
    details TEXT,
    action_by TEXT NOT NULL,
    action_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- suppliers: 供應商資料
CREATE TABLE suppliers (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL UNIQUE,
    contact_person TEXT,
    contact_phone TEXT,
    material_codes TEXT DEFAULT '[]',
    notes TEXT
);

-- supplier_formats: 供應商貨單格式（學習用）
CREATE TABLE supplier_formats (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    supplier_name TEXT NOT NULL,
    signature_keywords TEXT,            -- JSON: 特徵關鍵字
    extraction_patterns TEXT,           -- JSON: 學到嘅正則規則
    sample_image_path TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

| 命令 | 功能 | 模式 |
|------|------|------|
| `#到貨` | 引導式記錄到貨 | 逐步互動 |
| `#到貨快 <單號> <數量> <位置>` | 快指令到貨 | 一行+相片 |
| `#到貨查詢 <單號>` | 查詢單號狀態 | 即時回覆 |
| `#到貨匯出` | 生成總表 Excel | WhatsApp 發送 |
| `#今日到貨` | 今日到貨摘要 | 即時回覆 |
| `#追貨 <供應商>` | 供應商追貨清單 | 即時回覆 |
